# Security Notes

## Текущее состояние

Проект является клиентской Canvas-игрой без backend, базы данных, авторизации, cookies и сетевых API. В исходниках не должно быть секретов, токенов, приватных ключей или персональных данных.

## Что улучшено

- Удалены приватные контакты из README.
- Добавлен `.gitignore`, который исключает `.env`, ключи, архивы, IDE-файлы, временные файлы и зависимости.
- Добавлен базовый `tools/security-scan.mjs`.
- В HTML нет inline event handlers.
- В коде не используется `eval`.
- Ошибки запуска показываются пользователю общим сообщением, а технические детали остаются в консоли разработчика.
- Asset names проверяются через manifest и неизвестные имена падают явно.

## Правила на будущее

- Не хранить секреты в репозитории.
- Не выводить чувствительные данные в Canvas UI или console logs.
- Не использовать `innerHTML` для данных, которые могут прийти от пользователя.
- Не реализовывать права доступа только через UI, если появится backend.
- Для любых внешних данных добавить валидацию на границе входа.

## Ограничения

Базовый scan не заменяет полноценный SAST, dependency audit и browser security review. Сейчас в проекте нет runtime-зависимостей, поэтому dependency audit не применяется.
